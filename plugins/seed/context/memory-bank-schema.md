# Memory Bank — two-speed schema

Every command reads and writes the same store. There are two speeds, never one:

## Cold truth — markdown + git

The only layer that has to exist for the system to work. Fully reconstructible from
history. Never bypassed for a write; every fact the system relies on later must land
here before a command reports success.

```
memory-bank/
├── specs/
│   ├── SPEC-NEXUS.md              # present only when the work spans >1 module
│   └── SPEC-<module-id>.md        # one per module; module id is stable, kebab-case
├── tasks/<slug>.md                # plan + live execution state; slug IS the task id
├── roadmap/<feature>.md           # feature-level tracking, optional
│   └── versions/<version>.md      # groups features under a version; see roadmap.md
├── creative/<slug>-<type>.md      # design rationale, only when Creative ran
├── reflection/<slug>.md           # post-build analysis
├── archive/<slug>.md              # closed tasks
├── agent-rules/
│   └── _learned/                  # rules extracted by /seed:reflect, priority: low
├── agent-rules-index.md           # generated by /seed:rules-index — validation + index
└── projectConfig.md                # backend routing, branch policy, complexity overrides
```

No mutable registry file. The task list is what exists on disk; task history is `git log`
on the files above. A command that needs "all tasks" lists the directory, it does not
maintain a second index that can drift from it.

## Hot cache — local, disposable

```
memory-bank/.local/state.db              # gitignored, never a truth source
memory-bank/.local/session-logs/*.md     # one per session, written by the SessionEnd hook
memory-bank/.local/backend-drift.log     # append-only, per agent-backends.md fallback events
memory-bank/.local/last-test-exit-code   # written by build step 3, read by the commit guard
```

`state.db` holds the same facts as the cold layer, indexed for lookup instead of
full-file reads:

| Table | Mirrors | Read by |
|---|---|---|
| `spec_index` | module id → spec file, status, depends_on, blocked_by | `/seed:plan`, `/seed:spec-sync` |
| `phase_state` | current build phase per task, `NOT_STARTED`/`RUNNING`/`DONE` (matches `## Execution State`'s `Build Status`, not a RED/GREEN test-result field) | `/seed:build` |
| `citations` | every `SPEC-<id>.md#<heading>` reference found in the corpus | spec-corpus-hygiene pass |
| `learned_rules` | rule id → topic, priority, evidence_count, last_validated | every agent, on load |

The other three files are single-purpose, not part of the `state.db` schema: session logs
and the drift log are append/write-once evidence trails `/seed:doctor` and `/seed:reflect`
read; `last-test-exit-code` is a one-line handoff from build step 3 to step 6.

Rule: if `.local/state.db` is missing, stale, or suspected wrong, any command rebuilds it
by re-reading the cold layer — it is never edited directly, and losing it never loses a fact.
The other `.local/` files are each disposable in the same sense — losing one loses a
convenience (a session's evidence, one drift record, one guard check), never a fact only
they held.

## Why two speeds

A single markdown re-read per turn is what makes cost grow with project size. The hot
cache exists only to answer "what's the status of module X" or "what phase is task Y on"
without opening every file under `memory-bank/` — it is a lookup accelerator, not a second
opinion.
