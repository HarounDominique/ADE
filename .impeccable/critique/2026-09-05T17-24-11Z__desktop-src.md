## Design specificity verdict

ADE ya tiene rasgos propios —Project como contexto, Agents como conversación, Git como evidencia y el Explorer compacto/expandido—, por lo que no es una interfaz completamente intercambiable. Sin embargo, la implementación todavía parece una composición de iteraciones: el producto tiene una dirección clara en `DESIGN.md`, pero la cascada CSS y varias superficies legacy hacen que el resultado visible sea menos intencional de lo que promete la dirección `Sala de Evidencia`.

La inspección visual del `.app` confirmó una experiencia legible y funcional en Agents: rail de sesiones, conversación central, permisos/modelo y terminal transversal. El mayor problema no es la ausencia de elementos, sino que conviven demasiadas capas y algunos controles prometen más de lo que hacen.

## Priority issues

### [P1] El shell puede mostrar estado ficticio o perder evidencia

- **Ubicación:** `desktop/src/main.js:1494-1497`, `desktop/src/index.html:70`, renderers en `main.js:650`, `825`, `843`, `1260`, `2162`.
- **Por qué importa:** cuando el backend devuelve `tasks=[]`, el listado puede conservar `TASK-042` y `TASK-041`; además, varios renderers buscan nodos que ya no existen y retornan silenciosamente. En una herramienta basada en evidencia, esto erosiona la confianza.
- **Fix:** eliminar placeholders del markup inicial, renderizar `loading/empty/failed` desde estado real y borrar o reconectar renderers legacy. Añadir un contrato DOM que falle si un renderer apunta a un ID inexistente.
- **Comando sugerido:** `$impeccable harden`.

### [P1] La ventana inicial contradice el contrato responsive

- **Ubicación:** `desktop/src-tauri/tauri.conf.json:16-17`, `desktop/src/styles.css:522-524`.
- **Por qué importa:** Tauri abre en `800×600`, mientras la shell impone `min-width:900px` y `min-height:720px`, con `overflow:hidden`. En ventanas pequeñas pueden quedar ocultos controles, diffs o el composer.
- **Fix:** fijar `minWidth/minHeight` nativos coherentes con el layout y, además, diseñar un modo compacto real para anchos menores; no usar overflow oculto como sustituto de reflujo.
- **Comando sugerido:** `$impeccable adapt`.

### [P1] Accesibilidad incompleta en acciones principales

- **Ubicación:** `index.html:70` para tarjetas de Task; `index.html:56`, `74-76` para listbox/tabs; `index.html:86-94` para el diálogo de Task; `styles.css:475-487` para secundarios.
- **Por qué importa:** la selección de Task depende de click sobre `<article>`, los tabs/listbox no implementan completamente el patrón WAI-ARIA, el diálogo carece de nombre/descripción explícitos y `--muted`/`--faint` no alcanzan contraste AA para texto normal.
- **Fix:** usar botones/enlaces semánticos o `role/tabindex` con Enter/Espacio, navegación con flechas, `aria-controls`/`aria-labelledby`; asociar los diálogos a título/descripción y reservar colores de baja luminancia para metadatos no esenciales.
- **Comando sugerido:** `$impeccable harden`.

### [P1] La arquitectura visual todavía expone affordances y contexto fuera de lugar

- **Ubicación:** `index.html:16`, `index.html:82`, `styles.css:387-395`.
- **Por qué importa:** `Local workspace` muestra chevron y parece un selector sin comportamiento; el panel de documentación viva se muestra globalmente en vistas que no lo necesitan. Esto obliga al usuario a interpretar qué es accionable y añade ruido al foco de cada vista.
- **Fix:** completar el picker o convertirlo en contexto estático; mover el grafo/documentación a `Knowledge` y mantener sólo el contexto mínimo transversal.
- **Comando sugerido:** `$impeccable distill`.

### [P2] El sistema visual depende demasiado del orden de la cascada

- **Ubicación:** `styles.css:1-148`, `475-518`, `657-666`.
- **Por qué importa:** tokens duplicados, selectores legacy y colores hardcodeados hacen difícil predecir qué regla gobierna cada vista o tema. El resultado se percibe anguloso/discrepante aunque `DESIGN.md` sea más coherente.
- **Fix:** consolidar tokens semánticos por estado y tema, eliminar reglas de superficies retiradas, documentar excepciones del editor/terminal y establecer una única escala de radios/espaciado.
- **Comando sugerido:** `$impeccable document` seguido de `$impeccable polish`.

### [P2] Rendimiento y movimiento mejorables

- **Ubicación:** imports de `main.js:3-55`, transiciones de `styles.css:157`, `201`, `681-683`.
- **Por qué importa:** la pantalla inicial paga el coste de Monaco, múltiples lenguajes y Prettier aunque el editor no esté abierto; además, `prefers-reduced-motion` elimina casi toda transición, incluido feedback útil.
- **Fix:** cargar Monaco/lenguajes/formatter bajo demanda por vista/extensión, medir arranque y sustituir animaciones de layout por una estrategia de grid/opacity; para reduced motion eliminar desplazamiento pero conservar cambio visual de estado y mensajes live.
- **Comando sugerido:** `$impeccable optimize` y después `$impeccable animate`.
